# Xiaomi SU7 视角交互与悬浮控制菜单改版设计

**日期：** 2026-09-14  
**状态：** 待用户审阅  
**项目：** Xiaomi SU7 Interactive

## 1. 背景

当前页面已经具备四门控制、外观/座舱模式、主驾/副驾/后排视角、官方初代 SU7 9+4 配色、滚动叙事和按需渲染能力。本轮改版聚焦以下体验问题：

1. 删除不再需要的“影像”导航与影像展示区。
2. 删除“智能驾驶 / 传感器视角”滚动章节。
3. 滚动进入“智能座舱”时自动进入座舱并切换到后排默认视角。
4. 修正副驾默认镜头被副驾座椅或头枕遮挡的问题。
5. 让车外和座舱内都支持左右拖拽 360° 查看。
6. 将当前密集控制面板改为参考图所示的模块化深色悬浮菜单。
7. 色点不再常驻显示中文名称，以节省空间。
8. 提升九种官方车漆在当前 Three.js 灯光环境中的鲜亮度和漆面质感。
9. 在车辆右侧增加简洁的拖拽与滚动提示。

## 2. 已确认决策

- 删除整个“智能驾驶 / 传感器”滚动章节，而不是仅取消其相机切换。
- 故事章节保留：空气动力、性能、智能座舱。
- 进入智能座舱章节时自动切换为座舱模式和后排默认视角。
- 车外支持水平 360° 环绕查看。
- 座舱内支持以当前座位为原点的水平 360° 原地环视。
- 点击主驾、副驾、后排时，先恢复该座位默认视角。
- 用户拖拽结束后保留当前角度；滚动进入新章节或点击新座位时，自动相机重新接管。
- 菜单采用参考图的结构与视觉语言，但不机械复制尺寸。
- 颜色中文名不常驻显示；悬停、键盘聚焦及辅助技术仍可获得完整名称。
- 不引入新框架或第三方相机控制依赖。

## 3. 页面信息架构

### 3.1 顶部导航

导航由四项缩减为三项：

- SU7
- 细节
- 科技

删除：

- “影像”导航链接。
- `#film` 影像展示 Section。
- 影像资源导入和 `.brand-film` 专属样式。

### 3.2 滚动故事

滚动故事由四章缩减为三章：

1. `aero`：空气动力。
2. `performance`：性能。
3. `cabin`：智能座舱。

删除 `intelligence` 章节、传感器视角、相关文案和测试契约。

### 3.3 智能座舱章节

当 `cabin` 成为 active story：

- 自动将 `mode` 切换为 `cabin`。
- 自动将 `seatView` 切换为 `rear`。
- 必要时自动打开车门，沿用现有座舱进入流程。
- 相机先落到后排默认位置和目标点。
- 后续允许用户从该位置拖拽环视。

向上滚动离开该章节时，新的 story 相机预设重新接管；不保留上一次座舱手动朝向。

## 4. 视角控制设计

### 4.1 控制权状态

视角控制只有两种权威来源：

- `automatic`：章节滚动、模式切换、座位切换驱动的预设相机。
- `manual`：用户通过指针拖拽产生的相机偏移。

控制权切换规则：

1. 页面初始、章节变化、模式变化或座位变化时进入 `automatic`。
2. 用户按下并发生有效拖动后进入 `manual`。
3. 松手后保持 `manual` 朝向，不自动回弹。
4. 下一次章节、模式或座位变化清除手动偏移并恢复 `automatic`。
5. 模型加载失败、静态降级图显示或 stage hidden 时禁用拖拽。

### 4.2 车外拖拽

车外拖拽以车辆中心为观察目标：

- 水平角度连续累积，可完整旋转 360°。
- 纵向俯仰限制在安全范围，防止进入地面以下或俯视过度。
- 不开放自由缩放，保持车辆完整构图。
- 不直接永久旋转车辆根节点，避免影响车门轴、灯光方位和章节相机。
- 拖动通过相机球面偏移实现；预设相机仍是基础姿态。

### 4.3 座舱拖拽

座舱拖拽为第一人称原地环视：

- 相机位置固定在当前座位预设位置。
- 水平观察方向允许连续 360°。
- 纵向观察方向限制为自然抬头/低头范围。
- 不绕座椅公转，不改变相机座位原点。
- 对目标距离设置最小值，避免 target 穿过相机。
- 点击新座位后先恢复该座位默认 target，再开始新的手动偏移。

### 4.4 副驾默认镜头修正

当前副驾相机位于座椅靠背或头枕附近。新预设需要：

- 相机位置向前移动并略微向车内中心收拢。
- 默认 target 保持朝向仪表台与中控区域。
- 首帧不得被座椅、头枕或 B 柱大面积遮挡。
- 保持与主驾、后排相同的近裁剪面安全范围。

最终位置由真实 GLB 下的截图和像素/可见性验收确定，不仅依赖坐标推测。

### 4.5 指针与触屏

- 桌面鼠标：`grab` / `grabbing` 光标。
- 触屏：单指拖动。
- 使用 pointer capture 保证拖动连续。
- 在 `pointerup`、`pointercancel`、窗口失焦及控制器 dispose 时安全结束拖动。
- 拖拽开始时 `beginRenderActivity('view-drag')`。
- 拖拽过程中请求渲染。
- 拖拽结束时 `endRenderActivity('view-drag')` 并请求最终帧。
- `prefers-reduced-motion` 不禁用手动拖拽，但不增加惯性或回弹动画。

## 5. 悬浮控制菜单

### 5.1 视觉方向

参考图采用右侧模块化深色悬浮面板：

- 深色半透明背景。
- 轻微背景模糊。
- 低对比细边框和克制阴影。
- 外层圆角约 16–20px，内控件圆角约 10–12px。
- 图标、短文字和色点优先，避免长标签占据横向空间。
- 激活态通过较亮底色、描边和轻微缩放表达。

不照搬参考图中的具体宽度、品牌内容或模块数量；菜单仍以当前功能和响应式安全区为准。

### 5.2 菜单分组

桌面菜单按以下模块纵向堆叠：

1. 模式：外观 / 座舱。
2. 车漆：九个色点。
3. 内饰：四个色点。
4. 座位：主驾 / 副驾 / 后排。
5. 车门：开门 / 关门或当前简化门控。

规则：

- 外观模式隐藏或弱化座位分组。
- 座舱模式显示座位和内饰分组。
- 每个点击目标至少 44×44px。
- 保持现有 ARIA pressed 状态和键盘焦点环。
- 不依赖颜色本身表达选择状态；激活色点有描边和形态变化。

### 5.3 色点名称

- 色点内部不常驻显示中文名称。
- `aria-label` 保留完整官方名称。
- 鼠标悬停或键盘聚焦时显示 Tooltip。
- Tooltip 不改变面板布局、不遮挡车辆关键区域。
- 移动端通过长按/焦点或辅助文本提供名称，不要求触摸悬停。

### 5.4 响应式

- 桌面：菜单位于车辆右侧安全区，纵向堆叠。
- 中宽：菜单缩为紧凑模块或底部 dock，不覆盖 Hero、车辆 focus zone 或 cabin detail。
- 移动端：底部横向控制区，可分行滚动，但不得隐藏核心控制。
- `390×844`、`768×600`、`900×700`、`1280×800`、`1440×900` 为最低验收尺寸。

## 6. 操作提示

在桌面右侧、控制菜单附近增加低权重提示：

> 拖拽车辆查看外观细节  
> 滚动页面切换细节，右侧会跟随叙事自动调整视角

行为与样式：

- 不覆盖车辆、故事文案或菜单。
- 使用较小字号、低饱和浅色和充足行高。
- 可配一个简洁拖拽图标，但不引入新图标库。
- 座舱模式可将第一行动态替换为“拖拽视角查看座舱细节”，第二行保持不变。
- 移动端缩为一行或在首次进入时短暂显示，避免占用持续空间。

## 7. 官方配色与材质呈现

继续使用初代 SU7 官方九种外观与四种内饰的名称、顺序和身份。改版目标不是修改品牌色，而是在当前渲染环境中提升鲜亮度与漆面层次。

每种车漆允许单独配置：

- 基础色值。
- 金属度。
- 粗糙度。
- 清漆强度。
- 清漆粗糙度。
- 受控的亮度/饱和度补偿。

调校原则：

- 海湾蓝、熔岩橙、霞光紫增强色彩存在感和清漆反射。
- 流星蓝保持深蓝，不提亮成亮蓝。
- 珍珠白保持暖白与珠光，避免纯白塑料感。
- 钻石黑通过高光边缘体现形体，不把暗部提成灰色。
- 雅灰与寒武岩灰必须保持明显层级差异。
- 橄榄绿保持低饱和军绿色，不向荧光绿偏移。
- 所有颜色在 Hero、故事和座舱入口灯光下均不得出现大面积过曝。

由于 Three.js 材质颜色受环境贴图、曝光和色调映射共同影响，不把官网 CSS 色值直接等同于最终材质色；以官方视觉参考和渲染截图共同验收。

## 8. 代码边界

### 8.1 新增模块

新增独立 `view-drag-controller`：

- 输入：stage/canvas、当前模式、当前预设相机姿态、拖拽灵敏度和安全限制。
- 输出：手动 yaw/pitch 偏移、控制权变化、渲染活动生命周期。
- 不直接管理 story、seat 或 vehicle state。

### 8.2 现有模块职责

- `camera-controller`：默认章节与座位相机、自动过渡、应用手动偏移。
- `vehicle-state`：模式、座位、车门、车漆和内饰状态。
- `scroll-story`：三章滚动进度和 active story。
- `render-shell`：菜单、Tooltip、提示与删除后的页面结构。
- `bind-controls`：菜单交互绑定，不承担相机数学。
- `render-scheduler`：拖拽期间持续渲染，结束后回到按需渲染。
- `vehicle-palettes`：官方配色身份与每色材质参数。

## 9. 状态流

### 9.1 滚动进入智能座舱

1. `scroll-story` 激活 `cabin`。
2. state 设置 `activeStoryId='cabin'`。
3. mode 设置为 `cabin`。
4. seatView 设置为 `rear`。
5. camera-controller 清空手动偏移并过渡到 rear preset。
6. 视角到位后允许用户拖拽环视。

### 9.2 点击座位

1. seatView 更新。
2. camera-controller 清空手动偏移。
3. 过渡到所选座位默认 preset。
4. 拖拽控制器以新 preset 为基准继续工作。

### 9.3 用户拖拽

1. pointerdown 记录起点。
2. 超过最小移动阈值后切换为 manual。
3. pointermove 更新 yaw/pitch。
4. camera-controller 基于当前 preset 应用偏移。
5. pointerup 保持偏移并结束 render activity。

## 10. 降级与异常处理

- 模型加载失败或无 WebGL 时显示静态车辆图和重试按钮。
- 静态图状态不注册拖拽控制，不展示可交互光标。
- stage hidden/inert 时拖拽不可开始。
- context lost 时 dispose 当前拖拽监听和活动；restore 后从当前 state 重建，默认回到自动相机。
- 删除章节后不得残留无效 selector、ARIA、监听器或 diagnostics 字段。
- Tooltip 即使缺失也不能阻止颜色选择。

## 11. 测试与验收

### 11.1 单元测试

- 三章 story 数据结构和顺序。
- cabin story 自动切换 rear seat。
- 外观 yaw 可跨越 ±π 连续旋转。
- 座舱 yaw 360°，pitch 被安全限制。
- pointercancel/blur/dispose 结束 render activity。
- 章节、模式和座位切换清空手动偏移。
- 每种车漆材质参数合法且保持类型安全。
- 副驾 preset 不落入已知座椅遮挡区。

### 11.2 E2E

- 顶部导航仅有 SU7、细节、科技。
- 无 `#film`、影像资源、intelligence story 或传感器视角。
- 滚动进入 cabin 后 mode=cabin、seatView=rear、renderedView=rear。
- 三座位按钮恢复各自默认视角。
- 车外与三座位均可真实拖拽并改变相机/模型诊断状态。
- 拖拽后保持；滚动或座位切换后重置。
- 副驾首帧截图无遮挡。
- 九个车漆、四个内饰色点可操作且名称不常驻占位。
- Tooltip、ARIA、键盘操作完整。
- 菜单、提示、故事文案、车辆 focus zone 在最低验收尺寸无重叠。
- 四门反转、座舱灯光、stage exit、reduced motion 和 500ms idle rendering 不回归。

### 11.3 视觉验收

- 菜单体现参考图的模块化、深色玻璃、圆角和克制层级。
- 不出现参考图照搬式的品牌或不相关控件。
- 九种车漆明显更鲜亮，但无过曝或错误色相。
- 副驾、主驾、后排截图均可读。
- 车辆拖拽提示清楚但不抢主视觉。

### 11.4 交付验证

- Vitest 全量通过。
- TypeScript `tsc --noEmit` 通过。
- Production build 通过。
- Playwright 全量 `retries=0` 通过。
- 视觉快照经人工逐图确认。
- Production `dist` 不含 E2E diagnostics。
- GitHub Pages workflow 与线上页面验证通过后才算完成。

## 12. 非目标

本轮不包含：

- 双指缩放或鼠标滚轮缩放。
- 自由飞行相机。
- 物理惯性、自动回弹或陀螺仪控制。
- 新增车型、轮毂、性能参数或车身套件。
- 新增第三方 OrbitControls 或 UI 框架。
- 重新制作 GLB 模型几何或座椅网格。
