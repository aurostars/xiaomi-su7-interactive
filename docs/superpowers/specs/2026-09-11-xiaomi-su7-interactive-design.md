# Xiaomi SU7 三维交互官网设计规格

## 1. 项目目标

在独立仓库 `xiaomi-su7-interactive` 中搭建一套高相似度复刻的 Xiaomi SU7 三维交互官网，并通过 GitHub Pages 对外发布。

页面需要达到以下结果：

- 第一屏在视觉层级、色彩、排版和车辆占比上接近参考页面。
- 提供可信的 SU7 三维车辆展示，而不是临时几何体或低质量假模型。
- 支持外观与座舱模式、车漆与内饰换色、开关车门、座位视角和热点查看。
- 通过滚动驱动车辆镜头与内容章节同步变化。
- 在桌面端与移动端保持可用，并兼顾低性能设备与减少动态效果偏好。
- 构建产物可稳定运行在 GitHub Pages 的仓库子路径下。

参考页面：`https://magic.solutionsuite.cn/html-box/vk9vPHOMQU7`

## 2. 交付范围

### 2.1 页面结构

1. 顶部导航：品牌标识与 SU7、细节、科技、影像锚点。
2. 首屏车辆舞台：主标题、产品说明、双 CTA、三项核心指标与三维车辆。
3. 车辆控制：外观/座舱模式、车漆色板、内饰色板、开关车门。
4. 四段滚动叙事：空气动力学、电驱底盘、智能座舱、智能驾驶感知。
5. 科技内容区：800V 高压平台、智能驾驶感知、HyperOS 智能座舱。
6. 官方影像区：大幅品牌车辆视觉图。
7. 收尾 CTA：返回三维车辆舞台继续探索。
8. 页脚：品牌体验说明，不包含 Prototype、Demo、调试信息或内部链接。

### 2.2 核心交互

- 鼠标或触控拖拽旋转车辆。
- 切换车漆与内饰颜色，并即时反映到模型材质。
- “开门”仅控制车门动画，不自动进入座舱。
- “进入座舱”切换到车内相机，并可选择主驾、副驾和后排视角。
- 滚动进入各叙事章节时，相机位置、观察目标、车辆朝向与当前热点平滑过渡。
- 用户手动拖拽后，短时间暂停自动镜头，避免控制权冲突。
- 锚点导航、CTA 与返回按钮支持平滑滚动。

## 3. 技术架构

采用 Vite、TypeScript 与原生 Three.js。网站为纯静态应用，不依赖后端。

### 3.1 模块边界

- `scene`：渲染器、场景、相机、灯光、环境、阴影和尺寸适配。
- `vehicle`：GLB 加载、模型节点识别、材质映射、车门动画与车辆状态。
- `camera`：外观、热点和座舱相机预设，以及镜头插值。
- `controls`：拖拽旋转、模式切换、配色和座位选择。
- `scroll-story`：章节可见性检测、滚动进度与镜头叙事同步。
- `ui`：导航、首屏文案、控制面板、章节内容、科技卡片和错误提示。
- `performance`：设备能力判断、减少动态效果模式和渲染质量调整。

每个模块暴露清晰接口，页面 UI 不直接操作 Three.js 内部对象；状态变化通过统一的车辆与相机控制接口完成。

### 3.2 状态流

用户操作或滚动章节产生意图，进入统一状态层，再由车辆控制器和相机控制器更新 Three.js 场景。渲染循环只读取当前目标状态并进行平滑插值。

主要状态包括：

- 当前模式：外观或座舱。
- 当前车漆与内饰颜色。
- 车门开合状态。
- 当前热点或座位视角。
- 自动镜头是否暂时被手动拖拽覆盖。
- 模型加载、成功、失败与重试状态。

状态仅保存在浏览器当前会话，无需持久化或用户账户。

## 4. 视觉设计

### 4.1 设计语言

- 深黑背景配合低对比网格、冷青环境光和小米橙红强调色。
- 主标题使用高字重无衬线字体，首屏保持短句、强对比和充足留白。
- 车辆占据首屏主要视觉面积，文字位于左侧，控制面板悬浮在右上区域。
- 控件使用克制的细边框和半透明深色表面，不堆叠无意义标签。
- 内容章节通过大间距建立发布会式节奏，车辆舞台在滚动过程中保持视觉连续。
- 科技卡片使用统一比例的大图和简洁说明，避免多层卡片嵌套。

### 4.2 响应式

- 桌面端采用左右分区的车辆舞台与大尺度滚动叙事。
- 平板端缩小首屏文字和车辆占比，控制面板保持可点击。
- 移动端将文字、车辆和控制面板重排为纵向结构；保留模式切换、换色、热点和座舱视角。
- 移动端减少粒子、反射采样和高成本后处理，不取消核心操作。

## 5. 三维资源与性能

- 优先使用可信的 SU7 GLB 模型和正式品牌图片。
- 对模型采用适用的 Draco、Meshopt 或 KTX2 压缩，控制 GitHub Pages 下载体积。
- 页面骨架与首屏文本先显示，车辆模型异步加载。
- Loading 直接显示在车辆舞台中央，并展示可理解的加载进度或阶段。
- 大于 GitHub 单文件合理范围的资源放在允许跨域访问的对象存储，并记录来源与部署方式。
- 根据设备能力限制像素比、阴影分辨率、反射更新频率和后处理效果。
- 尊重 `prefers-reduced-motion`，降低滚动插值和非必要动画。

## 6. 错误处理

- 模型加载失败：在车辆舞台显示错误说明和重试按钮，同时用高质量静态车辆图兜底。
- 纹理或环境贴图失败：保留基础材质与灯光，避免整个场景不可见。
- WebGL 不可用：直接切换为静态车辆展示，页面内容与导航继续工作。
- 单个交互节点未在模型中找到：禁用对应按钮并记录开发期警告，不影响其他功能。
- 线上资源路径异常：在构建和 GitHub Pages 预览中检查所有请求，避免依赖站点根路径。

## 7. 测试与验收

### 7.1 功能验收

- 模型首次加载、失败提示和重试流程正常。
- 车辆拖拽旋转平滑，且不会与滚动镜头持续争抢控制权。
- 所有车漆和内饰选项能正确更新目标材质。
- 开门不会自动进入座舱；座舱按钮可进入车内。
- 主驾、副驾和后排视角空间关系合理。
- 四个滚动章节能触发对应镜头和热点。
- 锚点导航、CTA 和返回车辆舞台按钮工作正常。
- GitHub Pages 子路径下刷新任意可访问页面不会丢失资源。

### 7.2 视觉与性能验收

- 桌面端首屏在构图、色彩、排版和车辆占比上接近参考页面。
- 车辆是第一视觉主角，不出现重复车辆背景或无关技术说明。
- 关键控件在常见桌面和移动视口中不遮挡主要内容。
- 动画无明显跳变，滚动节奏不过快。
- 低性能与减少动态效果模式仍能完成核心浏览和交互。
- 生产构建成功，无阻断级控制台错误和资源 404。

## 8. GitHub Pages 发布

- 仓库名：`xiaomi-su7-interactive`。
- Vite `base` 配置为仓库子路径兼容模式。
- 使用 GitHub Actions 在默认分支更新时自动安装依赖、构建并发布 `dist`。
- 在推送远程仓库前先完成本地构建和部署产物检查。
- 创建远程仓库、推送代码和启用 Pages 属于远端写操作，执行前按用户确认进行。

## 9. 不在本次范围

- 后端 API、用户账户、数据库或内容管理系统。
- 在线购车、预约试驾、支付或真实门店能力。
- 多车型配置器。
- 原生移动应用或 PWA 离线安装。
- 与参考页面无关的品牌官网扩展页面。

## 10. 完成定义

项目满足以下条件即视为完成：

1. 本地生产构建通过。
2. 核心三维交互、滚动叙事和错误兜底通过验收。
3. 桌面与移动视口完成视觉检查。
4. GitHub Pages 自动部署配置可用。
5. 远程仓库创建并推送后，用户可通过公开 Pages 链接访问。
6. 页面不包含 Demo、Prototype、调试信息或无关跳转。
