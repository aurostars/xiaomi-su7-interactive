# Xiaomi SU7 参考站体验对齐设计

## 背景

当前站点已经完成四门控制、真实主驾/副驾/后排视角、座舱灯光与屏幕、响应式布局、加载降级和 GitHub Pages 发布。重新对比原参考站后，剩余主要差异集中在静态场景仍持续渲染、座舱暗部辨识度、四热点故事语义、首屏构图、地面空间感和控制面板密度。

本轮采用“参考站交互语义对齐 + 保留当前质量改进”的方向，不恢复参考站中已经被修正的门轴漂移、局部过曝、穿模和移动端遮挡。

## 目标

1. 静止场景不再持续占用每帧渲染，同时保证所有动画流畅。
2. 四个故事热点常驻，当前项高亮，右下详情卡常驻并与滚动、点击同步。
3. 三个座舱视角的方向盘、门板、座椅、中央通道等暗部结构可辨认。
4. 首页车辆更大、更低趴，并通过透视网格、接触阴影和半透明地块获得明确空间感。
5. 桌面端同时展示车漆与内饰色板，控制按钮增加统一图标并减轻面板视觉重量。
6. 保持四门、座席、移动端、无障碍、降级和生产诊断隔离能力不回归。

## 非目标

- 不进行框架迁移或引入新的 UI/动画依赖。
- 不增加自由轨道控制器或无限制缩放。
- 不追求参考站逐像素复制。
- 不改变现有文案主线、品牌导航与“预约试驾”入口。
- 不降低现有门轴准确性、座舱状态稳定性或移动端可用性。

## 方案选择

### 采用方案：语义对齐与定向强化

对齐参考站的热点、故事卡、控制面板和空间构图，同时保留当前更可靠的状态模型、门动画和响应式设计。该方案能最大化视觉与交互收益，且不需要重写 Three.js 场景。

### 未采用：逐像素复刻

会重新引入参考站的门轴、曝光、穿模和移动端遮挡问题，且对不同 GPU 和视口不稳定。

### 未采用：只调整灯光

无法解决热点语义、控制面板和持续渲染问题，整体体验仍与参考站存在明显结构差异。

## 架构设计

### 1. 渲染调度器

在 `create-scene.ts` 中将永久 RAF 循环改为活动驱动的调度器：

- `requestRender()`：请求至少一帧。
- `beginContinuousRender(reason)`：动画开始时进入连续渲染。
- `endContinuousRender(reason)`：对应活动结束后退出；所有 reason 清空后停止 RAF。
- `render()`：保留显式单帧渲染入口。
- `beforeRender` 与 `onRendered` 顺序保持不变。

活动来源包括：

- 相机向目标阻尼收敛；
- 四门运动；
- 座舱灯光过渡；
- 拖拽；
- 滚动故事相机变化；
- 窗口 resize；
- WebGL context 恢复；
- Store 中会改变可见结果的状态更新。

控制器通过返回 `boolean` 或暴露 `isAnimating()` 报告是否仍需下一帧。调度器只在至少一个活动源存在时继续 RAF。页面隐藏时暂停，恢复可见时请求一帧。

验收：静止 500ms 后 `renderRevision` 不再增长；动画期间连续增长；动画结束后再次稳定。

### 2. 故事热点状态

新增统一的 `activeStoryId`，可取：

- `aero`
- `performance`
- `cabin`
- `intelligence`

数据仍由既有 story 配置提供，UI 同时渲染四个 hotspot。每个热点包含：

- 稳定 `data-story-id`；
- 屏幕位置；
- 图标；
- 简短可访问名称；
- 当前状态 `aria-current`。

滚动故事更新 `activeStoryId`；热点点击设置同一状态并将对应故事段落滚入视口。相机、热点高亮、详情卡均订阅这一状态，不维护第二套当前章节。

右下详情卡默认可见，展示当前章节标题、说明与标签。点击当前热点不隐藏详情卡。

移动端不同时覆盖四个自由定位圆点，改为：

- 仅在车辆区域显示当前热点；
- 底部提供四项横向章节轨道；
- 详情内容在轨道上方显示；
- 轨道按钮与桌面热点使用相同 `activeStoryId`。

### 3. 座舱光照

继续使用独立 `cabin-light-rig`，不直接提高全局 exposure。

光照分层：

- 宽范围低强度冷灰环境补光，保证皮革和门板不死黑；
- 前排顶灯照亮方向盘、门板与中央通道；
- 后排补光照亮双前排椅背边缘和中央通道；
- 屏幕冷色光保持局部影响；
- 高画质保留脚部空间灯，中画质减少灯数，低画质仅使用环境补光与屏幕自发光。

每个座席允许具有小幅灯光权重差异，但不建立独立灯组。所有灯光继续在 240ms 左右平滑过渡。

验收：三座席视角中主要结构可辨认；屏幕和车顶无大面积纯白；外观模式不残留座舱灯。

### 4. 首页相机与空间构图

调整 `aero` 相机预设：

- 车辆视觉尺寸提高约 10%–15%；
- 相机高度略降，保持低趴姿态；
- FOV 保持低畸变范围；
- 1440×900 下四轮和车顶均不被裁切；
- 不侵入右侧控制面板或左侧主要标题。

场景增加独立的展示地面组：

- 低对比透视网格；
- 现有 ShadowMaterial 接触阴影；
- 青色与橙色半透明装饰地块；
- 地块位于车体下方，不穿过车轮或车门。

地面组不参与车辆材质更新，并在场景销毁时统一释放。低画质关闭装饰地块并降低网格密度。

### 5. 控制面板

桌面端：

- 外观/座舱切换保留；
- 车漆与内饰色板同时常驻；
- 座席按钮只在座舱模式启用并降低非活动态权重；
- 门按钮在任意可用车门存在时可用；
- 外观、座舱、开关门使用内联 SVG 线性图标，不引入图标库；
- 面板采用更轻的半透明表面、细内边框和统一冷灰层级。

移动端：

- 仍按当前模式收起次要控制，防止首屏过密；
- 保持至少 44px 触控尺寸；
- 座舱模式继续隐藏会与座舱卡冲突的 hero copy。

### 6. 动效与无障碍

- 热点默认只显示紧凑图标，悬停、聚焦或成为当前项时展开文本。
- 当前热点使用低幅度呼吸效果；`prefers-reduced-motion` 下取消脉冲。
- 故事卡切换使用 180–240ms 的 opacity/transform 过渡。
- 所有按钮保留 `focus-visible`、`aria-pressed` 或 `aria-current`。
- 不使用 `top/left` 驱动逐帧动画；动态位移使用 transform。

## 数据流

1. ScrollStory 或热点点击产生 `activeStoryId`。
2. VehicleStore 更新单一状态。
3. CameraController 根据当前故事和 mode 计算目标。
4. UI 同步四热点、详情卡和移动章节轨道。
5. 相关控制器请求连续渲染。
6. 所有动画完成后渲染调度器进入空闲。

门状态、座席状态、车漆和内饰色继续使用现有字段，不与故事状态耦合。

## 错误处理与降级

- WebGL 不可用或模型失败时继续展示静态 fallback；热点和控制面板禁用依赖 3D 的动作。
- 低画质关闭装饰地块、减少灯光与网格密度。
- reduced-motion 立即应用门、灯光、相机和故事卡终态，但仍请求最终渲染帧。
- context restore 后重新请求渲染并恢复当前 store 状态。
- 生产构建不得暴露 E2E diagnostics。

## 测试设计

### 单元测试

- 渲染调度：静止停止、活动连续、多个 reason 正确引用计数、dispose 后不再调度。
- 故事状态：滚动和点击共用 `activeStoryId`；四热点渲染；详情卡常驻。
- 控制器：相机、车门、灯光在动画结束时正确报告 idle。
- 控制面板：桌面双面板常驻；移动端互斥；图标和 ARIA 状态正确。
- 场景资源：网格、地块、灯光和材质释放幂等。

### E2E

- 首页车辆构图与控制面板无遮挡。
- 滚动四章节时，当前热点、详情卡和相机同步。
- 点击非当前热点后滚动到对应章节且卡片同步。
- 四门、座席和座舱关门保持现有行为。
- reduced-motion 和正常动画模式分别验证。
- 静止后 renderRevision 稳定，交互后重新增长。
- 移动端章节轨道、座舱卡、车辆焦点区不重叠。

### 视觉基准

- 首页 1440×900。
- 第一故事章节 1440×900。
- 主驾、副驾、后排 1440×900。
- 移动端依赖几何断言，避免跨平台 WebGL/字体像素差异造成假失败。

## 验收标准

1. 原参考站的四热点常驻、当前项高亮和常驻详情卡语义完整实现。
2. 当前站在静止状态停止连续 RAF，云端浏览器可稳定截图和执行交互。
3. 三个座舱视角暗部结构可辨认，无明显穿模、发灰或过曝。
4. 首页车辆占屏更大且保持完整，具有清晰地面空间感。
5. 桌面同时展示车漆与内饰，图标与玻璃面板视觉统一。
6. 四门、三座席、移动端、加载降级、context restore 和诊断隔离无回归。
7. 单元测试、TypeScript、生产构建、E2E 和视觉基准全部通过。
